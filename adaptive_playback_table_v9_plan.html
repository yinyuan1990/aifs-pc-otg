自适应网络与平滑降帧方案 v9（PC端 & iOS端）

✅ 目标

  • 极端弱网（1格信号）下仍能平滑降帧，避免卡顿和断流
  • 升降帧有滞后与平滑，避免频繁抖动
  • 控制闭环：接收端统计 → 发送端执行
核心结论：降帧/升帧必须由 iOS发送端执行，PC端提供反馈与决策建议。

📌 双端职责划分

模块 PC端（接收端） iOS端（发送端）
统计采样 到达率 / 抖动 / 丢包 / RTT / 队列帧数 编码队列 / 发送速率 / CPU负载
控制策略 计算目标帧率/码率建议 执行帧率/码率/分辨率调整
执行动作 仅反馈，不直接改码流 动态调参：fps/bitrate/scale
闭环链路 WebRTC stats + DataChannel/信令上报 接收反馈并落地执行

📊 关键指标（PC端采集）

指标 定义 计算方式 用途
到达率 实际到达 fps / 配置 fps arrivalFps / targetFps 稳定慢速识别
抖动比例 帧间隔抖动 / 期望间隔 J_ema / I_exp 预测式降帧
丢包率 lost / (lost + received) RTCP统计 拥塞判定
RTT 往返时延 RTCP统计 网络恶化判定
队列帧数 缓冲队列帧深 app queue depth 播放平滑控制

⚙️ 控制规则（PC端决策）

1) 降帧触发（满足任一即降）

条件 阈值 目标帧率 说明
到达率不足 < 85% 降到 arrivalFps 稳定慢速识别
抖动过高 J_ema / I_exp > 30% 线性降到 15fps 提前预测式
丢包偏高 > 5% 降 20%-40% 带宽拥塞
RTT过高 > 300ms 降 20%-40% 链路不稳定
队列下探 < 3帧 降到 20fps 播放保护

2) 升帧触发（需全部满足）

条件 阈值 说明
抖动稳定 J_ema / I_exp < 20% 网络恢复稳定
到达率充足 ≥ 90% 有余量
队列充足 ≥ 5帧 缓冲安全
持续时间 持续 ≥ 1s 防止抖动
升帧幅度：每次 +10% 当前帧率，且 不超过到达帧率与原始帧率。

🎯 iOS端执行策略（仅帧率，四档）

参数 调节优先级 建议范围
帧率 (fps) 最高 四档：60 → 45 → 30 → 15
码率 (bitrate) 次高 同步降 20%-50%
原则：不改变分辨率，只通过四档帧率平滑升降；码率随帧率同步微调。

🔁 闭环流程（推荐实现）

1) PC端每 1s 统计指标（到达率/抖动/丢包/RTT/队列）
2) PC端计算 targetFps / targetBitrate / targetScale
3) 通过 DataChannel/信令发送给 iOS 端
4) iOS端执行编码参数更新（即时生效）
5) PC端继续采样，进入下一轮闭环

🧠 关键公式（PC端）

期望间隔 I_exp = 1000 / fps
实际间隔 I_act = T_now - T_prev
瞬时抖动 J = |I_act - I_exp|
抖动EMA J_ema = 0.3 * J + 0.7 * J_ema
抖动比例 R = J_ema / I_exp
targetFps = min( fps_by_jitter, fps_by_arrival, fps_by_loss, fps_by_rtt, fps_by_queue )

💻 伪代码（PC端决策 + iOS端执行）

// ===== PC端：每1秒决策 =====
stats = collectStats(); // arrivalFps, jitter, loss, rtt, queueDepth

fps_by_arrival = (arrivalRate < 0.85) ? arrivalFps : currentFps;
fps_by_jitter  = (jitterRatio > 0.30) ? mapTo15fps(jitterRatio) : currentFps;
fps_by_loss    = (lossRate > 0.05) ? currentFps * 0.7 : currentFps;
fps_by_rtt     = (rttMs > 300) ? currentFps * 0.7 : currentFps;
fps_by_queue   = (queueDepth < 3) ? 20 : currentFps;

targetFps = min(fps_by_arrival, fps_by_jitter, fps_by_loss, fps_by_rtt, fps_by_queue);

if (canUpgrade(stats)) {
    targetFps = min(currentFps * 1.10, arrivalFps, originFps);
}

sendToIOS({ targetFps, targetBitrate, targetScale });

// ===== iOS端：执行 =====
applyEncoderParams(targetFps, targetBitrate, targetScale);
