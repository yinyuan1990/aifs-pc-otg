## 1. 控制端登录接口

### 基本信息

| 项目 | 内容 |
|-----|------|
| **接口地址** | `POST /api/auth/login/control` |
| **Content-Type** | `application/json` |
| **认证** | 不需要 Token |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| username | String | ✅ 是 | 控制端账号 |
| password | String | ✅ 是 | 登录密码 |
| deviceUsername | String | ❌ 否 | 指定要控制的设备账号，不传则默认最后绑定的设备 |

### 请求示例

**基础登录（默认最后绑定的设备）**：
```json
{
    "username": "control001",
    "password": "123456"
}
```

**指定设备登录**：
```json
{
    "username": "control001",
    "password": "123456",
    "deviceUsername": "device001"
}
```

### cURL 示例

```bash
curl -X POST http://localhost:9999/api/auth/login/control \
  -H "Content-Type: application/json" \
  -d '{
    "username": "control001",
    "password": "123456"
  }'
```

### 响应参数

| 参数名 | 类型 | 说明 |
|-------|------|------|
| token | String | JWT 令牌，后续请求需要携带 |
| username | String | 控制端账号 |
| userType | String | 用户类型，固定为 "控制端" |
| currentDeviceId | String | 当前选择的设备ID（没有绑定时为 null） |
| currentDeviceUsername | String | 当前选择的设备账号（没有绑定时为 null） |
| bindingList | Array | 已绑定的设备列表，见下方说明 |
| bindingCount | Integer | 绑定的设备数量 |
| membershipType | String | 会员类型 |
| status | String | 账号状态 |
| message | String | 提示信息 |

**bindingList 数组元素**：

| 参数名 | 类型 | 说明 |
|-------|------|------|
| bindingId | Long | 绑定记录ID |
| deviceUsername | String | 设备端账号 |
| deviceNickname | String | 设备端昵称 |
| deviceId | String | 设备ID |
| online | Boolean | 是否在线（true=推流中，false=离线） |
| bindTime | String | 绑定时间 |

### 错误响应示例

**账号密码错误**：
```json
{
    "error": "用户名或密码错误"
}
```

**账号类型错误**：
```json
{
    "error": "此账号不是控制端账号，请使用设备端登录"
}
```

**指定的设备未绑定**：
```json
{
    "error": "未绑定该设备: device999"
}
```

### 特殊说明

1. **deviceUsername 参数**：
   - 不传：使用最后绑定的设备
   - 传了且已绑定：使用指定的设备
   - 传了但未绑定：返回错误

2. **没有绑定任何设备时**：
   - `currentDeviceId` 和 `currentDeviceUsername` 都为 `null`
   - `bindingList` 为空数组 `[]`
   - `bindingCount` 为 `0`

3. **online 字段**：
   - `true`：设备端正在推流
   - `false`：设备端未推流或已离线

## 2. 查询绑定设备列表接口

### 基本信息

| 项目 | 内容 |
|-----|------|
| **接口地址** | `GET /api/binding/devices` |
| **Content-Type** | 无 |
| **认证** | 不需要 Token |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| controlUsername | String | ✅ 是 | 控制端账号（URL Query 参数） |

### 请求示例

```
GET /api/binding/devices?controlUsername=control001
```

### cURL 示例

```bash
curl -X GET "http://localhost:9999/api/binding/devices?controlUsername=control001"
```

### 响应参数

| 参数名 | 类型 | 说明 |
|-------|------|------|
| devices | Array | 设备列表 |
| count | Integer | 设备数量 |

**devices 数组元素**：

| 参数名 | 类型 | 说明 |
|-------|------|------|
| bindingId | Long | 绑定记录ID |
| deviceUsername | String | 设备端账号 |
| deviceNickname | String | 设备端昵称 |
| deviceId | String | 设备ID |
| online | Boolean | 是否在线（true=推流中，false=离线） |
| bindTime | String | 绑定时间 |

### 成功响应示例

```json
{
    "devices": [
        {
            "bindingId": 1,
            "deviceUsername": "device001",
            "deviceNickname": "我的iPhone",
            "deviceId": "9F0B44DC-76A5-433B-8DB8-D3187E05A459",
            "online": true,
            "bindTime": "2025-11-25T10:31:00"
        },
        {
            "bindingId": 2,
            "deviceUsername": "device002",
            "deviceNickname": "iPad Pro",
            "deviceId": "ABC123DE-F456-7890-GHIJ-KLMNOPQRSTUV",
            "online": false,
            "bindTime": "2025-11-24T15:20:00"
        }
    ],
    "count": 2
}
```

### 没有绑定设备时的响应

```json
{
    "devices": [],
    "count": 0
}
```

### 错误响应示例

**控制端账号不存在**：
```json
{
    "error": "用户不存在"
}
```

### 使用场景

1. 登录后刷新设备列表
2. 检查设备在线状态
3. 切换控制的设备

## 3. 手动绑定设备接口

### 基本信息

| 项目 | 内容 |
|-----|------|
| **接口地址** | `POST /api/binding/manual-bind` |
| **Content-Type** | `application/json` |
| **认证** | 不需要 Token |

### 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| controlUsername | String | ✅ 是 | 控制端账号 |
| deviceUsername | String | ✅ 是 | 设备端账号 |
| password | String | ✅ 是 | 设备端的登录密码 |
| secondaryPassword | String | ✅ 是 | 设备端的二级密码 |

### 请求示例

```json
{
    "controlUsername": "control001",
    "deviceUsername": "device001",
    "password": "123456",
    "secondaryPassword": "second456"
}
```

### cURL 示例

```bash
curl -X POST http://localhost:9999/api/binding/manual-bind \
  -H "Content-Type: application/json" \
  -d '{
    "controlUsername": "control001",
    "deviceUsername": "device001",
    "password": "123456",
    "secondaryPassword": "second456"
  }'
```

### 响应参数

| 参数名 | 类型 | 说明 |
|-------|------|------|
| success | Boolean | 是否成功 |
| bindingId | Long | 绑定记录ID |
| controlUsername | String | 控制端账号 |
| deviceUsername | String | 设备端账号 |
| deviceId | String | 设备ID |
| status | String | 绑定状态，成功时为 "ACTIVE" |
| message | String | 提示信息 |
| bindCompleteTime | String | 绑定完成时间 |

### 成功响应示例

```json
{
    "success": true,
    "bindingId": 1,
    "controlUsername": "control001",
    "deviceUsername": "device001",
    "deviceId": "9F0B44DC-76A5-433B-8DB8-D3187E05A459",
    "status": "ACTIVE",
    "message": "绑定成功",
    "bindCompleteTime": "2025-12-08T10:30:00"
}
```

### 错误响应示例

**参数缺失**：
```json
{
    "error": "控制端账号不能为空"
}
```

```json
{
    "error": "设备端账号不能为空"
}
```

```json
{
    "error": "设备端密码不能为空"
}
```

```json
{
    "error": "二级密码不能为空"
}
```

**账号验证失败**：
```json
{
    "error": "控制端用户不存在"
}
```

```json
{
    "error": "设备端用户不存在"
}
```

```json
{
    "error": "该账号不是控制端"
}
```

```json
{
    "error": "该账号不是设备端"
}
```

**密码验证失败**：
```json
{
    "error": "设备端密码错误"
}
```

```json
{
    "error": "二级密码错误"
}
```

**绑定限制**：
```json
{
    "error": "已经绑定过该设备"
}
```

```json
{
    "error": "该设备已达到最大绑定数量限制：5"
}
```

### 特殊说明

1. **与扫码绑定的区别**：
   - 扫码绑定：需要设备端和控制端双方都输入二级密码验证
   - 手动绑定：只需要控制端输入设备端的账号和密码，直接绑定成功

2. **重复绑定**：
   - 如果之前已解绑，再次绑定会复用原来的绑定记录
   - 如果当前是 ACTIVE 状态，会返回错误 "已经绑定过该设备"

3. **绑定数量限制**：
   - 每个设备端最多被 5 个控制端绑定（可配置）
   - 控制端可以绑定多个设备端（无限制）

## 附录

### A. 错误码说明

所有接口的错误响应格式统一为：

```json
{
    "error": "错误描述信息"
}
```

### B. 在线状态说明

| online 值 | 说明 |
|----------|------|
| `true` | 设备端正在推流（publishStatus=1） |
| `false` | 设备端未推流或已断开连接 |

在线状态通过 Redis 缓存，有效期 10 秒。如果设备端超过 10 秒没有上报状态，会自动变为离线。

### C. 接口调用流程

#### 首次使用

```
1. 调用手动绑定接口，绑定设备
   POST /api/binding/manual-bind
   
2. 调用登录接口，获取 Token 和设备信息
   POST /api/auth/login/control
   
3. 使用 currentDeviceId 进行后续操作
```

#### 日常使用

```
1. 调用登录接口
   POST /api/auth/login/control
   
2. 从 bindingList 中选择要控制的设备
   
3. 如需切换设备，重新登录并传入 deviceUsername
   POST /api/auth/login/control
   {"username": "xxx", "password": "xxx", "deviceUsername": "device002"}
```

#### 刷新设备列表

```
调用查询接口，获取最新的设备列表和在线状态
GET /api/binding/devices?controlUsername=control001
```
