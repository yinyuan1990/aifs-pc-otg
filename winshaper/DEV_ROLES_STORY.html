谁在做这件事？

按角色串起整条开发线，再用普通人能懂的比喻对照——说的是「给电脑上的软件限速上网」这类功能，从想法到能用的过程。

总比喻：城市快速路 + 收费站

把网线想成出城快速路：路上跑的全是一辆辆小货车（数据包），每辆车属于某家公司车队（某个软件，比如浏览器）。 我们要做的是：在不拆路、不改红绿灯系统的前提下，给指定车队设一个「每分钟最多过几辆车」的口子——就像可变车道收费站：认车牌（认是哪个软件）、计数、排队、放行。 技术团队就是在修路公司允许的护栏位置（WinDivert / 系统接口）装这套计数设备；若自己从路基挖洞做管道（自研内核驱动），就变成市政级工程，难度和审批都高得多。

一、登场角色（剧组名单）

业务 / 产品 架构师 Windows 网络 / 系统工程师 后端开发 客户端 / 服务开发 测试工程师 运维 / 实施 法务 / 合规

二、每个角色干什么？（带比喻）

业务 / 产品经理 定「要啥」

比喻：市政委托方——说清楚「哪些车队要限、限多严、什么时候限、出事了谁负责」，不写代码，但决定工程值不值得做。

把「限速 Chrome 上传、下载先不管」写成可验收的条目；和法务一起确认能不能采集进程信息、要不要用户同意等边界。

架构师 选「走哪条路」

比喻：总设计师——决定是租用现成的收费站设备（集成 NetLimiter 等 API）、在公路护栏官方接口上装 WinDivert，还是自己铺一条专用匝道（自研 WFP/NDIS 驱动）。

权衡：开发周期、授权与 LGPL、是否要签微软驱动、上线后谁维护。输出一张「模块图」：后台指令 → 本机服务 → 限速引擎 → 系统网络栈。

Windows 网络 / 系统工程师 装「收费站」

比喻：真正懂这段路牌和护栏规格的工程师——知道包从哪进、PID 怎么对上、IPv4/IPv6、TCP/UDP、VPN 会不会绕路。

实现或裁剪 WinDivert 方案：SOCKET 层「认车牌」、NETWORK 层「数车放行」、令牌桶与队列；处理竞态、队列满、异常流量。自研驱动时，这一角色权重最大、风险最高（蓝屏、签名）。

后端开发 发「调度令」

比喻：交通指挥中心——把策略存在服务器，在需要的时候给某台电脑发「现在开始限某某软件」的指令，不负责在车里装刹车。

设计 API / WebSocket 消息、设备身份、鉴权、审计日志；与客户端约定 JSON 字段（exe、上行速率、生效时间等）。

客户端 / 服务开发 听令执行

比喻：路口值班亭——24 小时听着对讲机（网络），把中心的话翻译成「收费站旋钮拧到多少」，无界面也可以，只要进程能跑、能重启、能写日志。

接收后台指令，更新规则文件或内存里的规则表；可选：守护进程、开机启动、与主程序联动。把「人话」变成 winshaper 能吃的配置。

测试工程师 压马路

比喻：试车员和交警联合演练——大文件上传、看视频、打游戏、开 VPN、多网卡、休眠唤醒，看会不会堵死、漏限、误伤别的软件。

记录：首包是否偶发不限速、队列满时是否短时冲顶、IPv6/UDP 未覆盖时的预期行为。输出版本能否给「普通人用」的结论。

运维 / 实施 上路运营

比喻：养路队——保证收费站在客户机器上能装上、驱动能加载、升级不翻车、出问题能远程看日志或回滚规则。

打包 WinDivert 组件与许可说明、管理员权限说明、与杀软冲突时的处理手册。

法务 / 合规 红线

比喻：交通局法规科——第三方组件 LGPL 怎么贴声明、用户协议里要不要写「会识别进程名」、某些场景是否涉及监控合规。

不挡技术选型，但决定「能不能卖、怎么写隐私政策」。

三、时间顺序：故事怎么演？

  1. 第 1 幕 · 立项
    产品 + 法务框需求；架构师选定 WinDivert / 集成 / 自研之一。
  2. 第 2 幕 · 修路基
    网络工程师做出「能限 IPv4 TCP」的雏形（类似当前仓库里的 winshaper）；后端定协议草案。
  3. 第 3 幕 · 联网
    客户端服务接上后台，能远程改规则；先做「只限上传」时，规则里下载填 0 即可。
  4. 第 4 幕 · 长测
    测试在各种电脑上压场景；修竞态、队列策略、日志与降级。
  5. 第 5 幕 · 交付
    运维出安装包与文档；法务最终过许可与用户条款。

给完全外行的一句话

这不是「给软件窗口里加一个按钮」那么简单，而是在高速公路上给特定公司的货车单独设限速——需要认车的人（系统工程师）、下命令的人（后端）、在路口执行的人（客户端），再加试车的人和看法规的人，一起才能把戏演完。
