子进程 zjc_worker — 流量整形 STOMP 约定（与 winshaper.exe 联调）
================================================================

订阅（客户端已写死，后端需向这些 destination 发 MESSAGE）：
  /topic/pc/{pcDeviceId}/shaper
  /topic/shaper/all

JSON 正文字段（与 BURST 一样放在 STOMP frame body 里）：

1) 开始限速（仅当 processName 在系统中存在匹配进程时才启动 winshaper）
   action: "TRAFFIC_SHAPE"
   taskId: string（建议唯一，便于对账）
   processName: string（可与 BURST 一样写 chrome / chrome.exe，匹配规则同 procNameMatch）
   可选别名键: "process" 同 processName
   uploadBps: number（字节/秒，0 表示该方向不限速）
   可选别名: upBps
   downloadBps: number
   可选别名: downBps
   durationSec: number（可选，0 = 直到 TRAFFIC_SHAPE_STOP；最大 86400）
   至少 uploadBps、downloadBps 之一须 > 0，否则 skipped。

2) 停止
   action: "TRAFFIC_SHAPE_STOP"
   taskId: string（可选，当前实现不校验 taskId，一律结束子进程 winshaper）

上报（客户端 POST SEND）：
  destination: /app/subprocess/shaper-result
  JSON:
    { pcDeviceId, username, taskId, ok: true|false,
      skipped?: true, reason?: "no_process_name"|"no_matching_process"|"no_rates_specified",
      timestamp }

部署（二选一）：
  A) 内嵌编译（推荐打包）：在 winshaper/third_party/WinDivert 放好官方 SDK 后 CMake 默认 ZJC_EMBED_WINSHAPER=ON，
     仅需发布 zjc_worker.exe + WinDivert.dll/sys；子进程用「自身路径 --zjc-shaper <rules>」拉起整形，无需单独 winshaper.exe。
  B) 未内嵌：zjc_worker.exe 与 winshaper.exe 同目录；均需能加载 WinDivert（通常管理员）。
