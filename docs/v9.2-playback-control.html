🎬 GstPlayer v9.2 播放控制方案

基于实际到达帧率EMA的自适应播放控制系统

📐 核心原理

v9.2的核心改进是基于实际到达帧率（arrivalRateEMA）而非配置帧率来计算所有阈值。

关键公式：
arrivalFps = EMA(实际接收帧率, α=0.3)
queueOptimal = arrivalFps × 22% (≈220ms延迟)
queueMin = arrivalFps × 15% (≈150ms延迟)
queueMax = arrivalFps × 47% (≈470ms延迟)
实际延迟 = 队列帧数 × 1000 / arrivalFps + 350ms(GStreamer)

示例（30fps）

参数 计算 结果
最佳队列 30 × 22% 7帧 (≈233ms)
最小队列 30 × 15% 5帧 (≈167ms)
最大队列 30 × 47% 14帧 (≈467ms)

🛡️ 第一道防线：播放速度控制

通过调整播放速度来控制队列深度，实现稳定的低延迟播放。

速度控制逻辑

队列状态 目标速度 调整方式 说明
队列 = 0 70% 立即 队列空，紧急降速等待帧到达
队列 ≤ 2帧 85% 立即 队列危险，快速降速
队列 < 最小值 92% 平滑 队列偏少，温和降速积累缓冲
队列 在范围内 100% 平滑 正常播放
队列 > 最大值 110% 立即 队列堆积，立即追帧

v9.2 关键改进：快速恢复

当前速度 < 目标速度
且队列 ≥ 最佳值
→
立即恢复到目标速度
当前速度 < 90%
且队列 < 最佳值
→
快速恢复每次+15%
其他情况
→
平滑调整每次±5%

🔧 第二道防线：推流帧率控制（升降帧）

当播放速度无法应对时，请求前端调整推流帧率。

📉 降帧条件（满足任一）

条件 阈值 持续
水位触发 < 35% 1秒
延迟触发 > 500ms 1秒

降帧目标计算

水位触发：
ratio = (35% - 水位) / 30%
目标fps = 60 - (60-20) × ratio

延迟触发：
ratio = (延迟 - 500) / 300
目标fps = 60 - (60-15) × ratio

📈 升帧条件（全部满足）

条件 阈值
已在降帧状态 requestedFps > 0
延迟恢复 200ms ~ 500ms
水位稳定 ≥ 50%
持续时间 1秒

升帧步长

step = max(1, 当前fps × 10%)
目标fps = min(当前fps + step, 原始fps, 到达fps)

✅ v9.2 已修复

延迟阈值已调整为与新缓冲策略匹配：

  • 降帧触发：延迟 > 500ms（超过最大缓冲470ms）
  • 降到最低：延迟达到 800ms
  • 升帧恢复：延迟在 200ms-500ms 之间

🚨 紧急保护机制

触发条件

队列 == 0
→ emergencyHold = true
→ 停止消耗，使用最后有效帧

解除条件

队列 > 0
→ emergencyHold = false
→ 立即恢复消耗

网络严重恶化自救

当 到达帧率 < 配置帧率 × 50% 时：

  1. 请求降帧到15fps
  2. 请求关键帧
